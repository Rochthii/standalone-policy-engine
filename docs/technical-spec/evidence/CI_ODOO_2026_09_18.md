# CI Odoo E2E recovery evidence — 2026-09-18

## Scope

The GitHub Actions run for `d5eb973536db49fdc728589a8f0a09c84bfcf10d`
failed only in `Real Odoo PostgreSQL gRPC E2E`. The first command in
`make test-odoo-e2e` failed because the hardened PDP image runs as UID 10001,
while fresh named volumes are created with root ownership.

The testbed now uses root only in ephemeral initialization containers: one
creates the short-lived TLS material and one assigns the audit spill volumes to
UID/GID 10001 with mode `0700`. Both PDP services remain non-root.

## Local validation

Windows does not provide GNU Make, so the two Compose commands used by the
Make target were run directly against fresh testbed volumes:

```bash
docker compose -f docker-compose.testbed.yml --profile e2e run --build --rm testbed-certgen
docker compose -f docker-compose.testbed.yml --profile e2e up --build \
  --abort-on-container-exit --exit-code-from testbed-odoo-e2e testbed-odoo-e2e
```

Observed results:

- `MTLS-CERTGEN PASS` wrote the short-lived CA, server and Odoo client
  certificates.
- `testbed-pdp-mtls` became healthy while running as the hardened image user.
- The mTLS negative boundary check passed.
- Odoo reported `0 failed, 0 error(s) of 8 tests`; the seven transaction cases
  and the two-session concurrency assertion passed.
- `ODOO-CONCURRENCY PASS: 2 sessions, 1 nonce, 1 executed attempt` was
  emitted.
- `docker compose ... config --quiet` and `git diff --check` passed.

The testbed containers, network and named volumes were removed after the run.
