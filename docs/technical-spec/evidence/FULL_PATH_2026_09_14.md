# Full PDP Path Evidence — 2026-09-14

## Scope

`PERF-FULL-02` measures 10,000 sequential `CheckAccess` requests over one persistent loopback TCP gRPC connection. Each measured request performs server-side JWT validation and tenant/subject binding, full-tuple HMAC delegation-proof verification, policy evaluation, Prometheus metric updates, and redacted/encrypted audit queueing. The asynchronous audit worker drains to an in-process batch writer before the test ends.

This is a local application-path measurement, not a production deployment measurement: transport is insecure loopback TCP, the audit sink is not PostgreSQL, and the run excludes mTLS, revocation synchronization, database latency, Odoo and concurrent load.

## Reproduction

Commit: `2e5c44dc14118f10015d577fa669441a5c584bd3`. Environment: Windows/amd64, 13th Gen Intel(R) Core(TM) i7-13700H, Go `go1.26.4`. Per-RPC latency uses Windows `QueryPerformanceCounter`; `time.Now` was rejected because its observed clock resolution produced zero-duration samples.

```powershell
$env:RUN_PERF_FULL='1'
go test ./tests -run TestFullPathEvidence -count=3 -v
```

CPU is process CPU time divided by wall time, so it includes both client and server goroutines in the same process and may exceed 100%. RSS is the process working set. All 30,000 measured requests returned `ALLOW`; error count was zero.

## Interpretation

The measurement demonstrates a reproducible local path beyond the in-memory evaluator. It does not establish a production E2E latency SLO: mTLS, durable PostgreSQL audit flush, revocation storage/synchronization, container networking, Odoo and concurrent-client saturation remain separately measurable boundaries.
