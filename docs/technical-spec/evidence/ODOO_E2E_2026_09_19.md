# Odoo 17 Real-Boundary E2E Evidence — 2026-09-19

## Scope and environment

This run crossed `Odoo 17 ORM -> generated Python gRPC client -> mutual TLS -> Go PDP -> PostgreSQL 15` on commit `e243db5`. Docker Engine was `29.1.3`; Odoo reported `17.0-20260908`; PostgreSQL used the isolated `odoo_e2e` database. The testbed generated an ephemeral ECDSA P-256 CA and mTLS server/client certificates.

The PDP service ran with `APP_ENV=test`, real mTLS and PostgreSQL. No external audit archive was configured. This is testbed E2E evidence, not production, WORM or cloud evidence.

## Reproduce

```bash
docker compose -f docker-compose.testbed.yml --profile e2e run --build --rm testbed-certgen
docker compose -f docker-compose.testbed.yml --profile e2e up --build \
  --abort-on-container-exit --exit-code-from testbed-odoo-e2e testbed-odoo-e2e
```

## Result

- `MTLS-BOUNDARY PASS`: no client certificate and wrong hostname were rejected; the valid Odoo certificate reached the JWT boundary.
- Seven transaction cases passed: ALLOW idempotency; non-rollback human approval; SoD rollback; outage fail-closed; live revocation; tampered proof denial; altered-command nonce replay denial.
- Two independent Odoo/PostgreSQL sessions contended for one nonce. One serialization failure retried through Odoo and the final result was `1 nonce`, `1 executed attempt`, and `state=purchase`.
- Container exit code: `0`; Odoo reported `0 failed, 0 error(s) of 8 tests`. The eighth post-test is the separately bounded ORM benchmark; its raw result is recorded in [`ODOO_ORM_COMPARISON_2026_09_15.json`](./ODOO_ORM_COMPARISON_2026_09_15.json).
